### Harness Engineering

* 하네스 구성 요소는 크게 3가지가 있다.
  * Planner : 명확한 스펙(무엇을 만들지 구체적인 스펙)
  * Contract : 스프린트 계약(완료 기준을 코드 작성 전에 합의)
  * Evaluator : 자동 테스트(실제 브라우저에서 자동 검증)
* 하네스 설계의 6가지 구성요소 = 규칙 전달(CLAUDE.md) + 위험 차단(Permissions) + 자동 검증(Hooks) + 테스트 도구(MCP) + AI 분리(Subagent) + 진화 원칙(메타 원칙)

#### 1. 규칙 전달 CLAUDE.md

* AI가 실수를 하면 문서에 규칙을 추가한다.
* 이 사이클을 반복해 같은 실수 반복을 방지한다.
* Claude Code에서는 CLAUDE.md로 매 세션 규칙을 자동으로 전달한다. 세션이 바뀌어도 규칙은 매번 전달된다.

#### 2. 위험 차단(Permissions)

* 규칙을 알려주는 것(맥락, 부탁)과 아예 못하게 막는 것(강제, 차단)은 다르다.
* `allow`, `deny`로 도구 사용 범위를 설정한다.
```json
{
    "allow" : [
        "Read", "Edit", "Write"
    ],
    "deny" : [
        "Bash(rm -rf *)"
    ]
}
```

#### 3. 자동 검증(Hooks)

* CLAUDE.md에 테스트를 꼭 돌리라고 적어둘 수 있지만 이렇게 적을 필요가 없다.
* 도구 사용 전/후에 스크립트가 자동으로 실행되도록 할 수 있다.
    * AI가 코드를 수정한다.
    * Hook이 자동으로 테스트를 실행한다.
    * 실패 시 결과가 AI에게 전달된다.

#### 4. 테스트 도구(MCP)

* 코드만 봐서는 알 수 없는 버그가 있다.
    * Claude Code로 실행한다.
    * MCP Server를 사용한다.
    * Playwright로 브라우저 실행 & 테스트를 진행한다.
    * 결과 피드백 → Claude Code로 전송한다.

#### 5. 진화 원칙(메타 원칙)

* 규칙이 불필요하다면 삭제하고 새로운 실패 케이스가 발생하면 즉시 추가한다.
