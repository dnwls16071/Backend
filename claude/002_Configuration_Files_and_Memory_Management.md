### settings.json

* `.claude/settings.json`은 Claude의 명령 실행 권한과 파일 접근 범위를 정의한다.
* `$schema` 필드는 VS Code 등에서 자동 완성과 유효성 검사를 지원한다.
* `allow` 목록은 자동 승인 명령, `deny` 목록은 완전 차단 명령 지정한다.
    * 예: 허용 — Bash (npm run *), Read, Write, Edit
    * 차단 — Bash (rm -rf *), Bash (curl *), .env 파일 읽기
* 목록에 없는 명령은 실행 전 사용자 확인 요청한다.
* 개인별 권한 변경은 `.claude/settings.local.json`에 저장되며 Git에 포함되지 않는다.

### CLAUDE.md

* **LLM의 무상태성과 CLAUDE.md의 역할**
    * LLM은 추론 시점에 고정된 가중치를 사용하며, 세션 간 학습이나 기억을 유지하지 않는다.
    * 따라서 모델이 코드베이스를 이해하려면 입력 토큰으로 모든 정보를 제공해야 한다.
* Claude Code 같은 코딩 에이전트는 메모리를 명시적으로 관리해야 하며, `CLAUDE.md`는 모든 대화에 자동 포함되는 유일한 파일이다.
* 이로 인해 다음 세 가지가 필수적이다.
    * 세션 시작 시 Claude는 코드베이스에 대해 아무것도 모른다.
    * 매 세션마다 필요한 정보를 다시 알려야 한다.
    * 이를 위한 표준 수단이 `CLAUDE.md`이다.
* **코드베이스 온보딩: WHAT, WHY, HOW**
    * `CLAUDE.md`는 Claude가 프로젝트를 이해하도록 돕는 온보딩 문서 역할을 한다.
        * WHAT: 기술 스택, 프로젝트 구조, 모노레포 구성 등 코드 지도를 제공
        * WHY: 각 구성 요소의 목적과 기능을 설명
        * HOW: 빌드·테스트·타입체크 등 실제 작업 수행 방법을 명시
* **좋은 `CLAUDE.md` 작성 원칙**
    * LLM은 집중적이고 관련성 높은 문맥에서 더 잘 작동한다.
    * `CLAUDE.md`는 모든 세션에 포함되므로, 보편적으로 적용 가능한 정보만 유지해야 한다.
    * 일반적으로 300줄 미만, 가능하면 더 짧게 유지하는 것이 권장된다.
* **Progressive Disclosure**
    * 대형 프로젝트에서는 모든 정보를 한 파일에 담기 어렵기 때문에, 점진적 공개 (Progressive Disclosure) 방식을 권장한다.
        * 세부 지침은 `agent_docs/` 폴더 내 별도 마크다운 파일로 분리한다.
        * 예: building_the_project.md, running_tests.md, code_conventions.md 등
    * `CLAUDE.md`에는 이 파일들의 목록과 간단한 설명, 그리고 Claude가 필요 시 읽도록 하는 지시만 포함한다.
    * 코드 스니펫 대신 file:line 참조를 사용해 최신성을 유지한다.
    * 이는 Claude Skills 개념과 유사하나, 도구 사용보다는 지시 관리에 초점을 맞춘다.
* **Claude는 린터가 아니다.**
    * 코드 스타일 가이드라인을 CLAUDE.md에 포함하는 것은 비효율적이다.
        * LLM은 비용이 높고 느리며, 린터보다 비결정적이다.
    * 스타일 규칙은 기존 코드 패턴을 통해 자연스럽게 학습되므로 별도 지시 불필요하다.
    * 포맷팅은 자동 수정 가능한 린터 (Biome 등) 를 활용하고, Claude에는 수정 결과만 전달한다.
    * 필요 시 Stop Hook이나 Slash Command를 사용해 포맷팅·검증을 자동화한다.
* **자동 생성 금지를 권장한다.**
    * `/init` 명령이나 자동 생성 기능으로 만든 `CLAUDE.md`는 비추천한다.
        * 이 파일은 모든 세션과 산출물에 영향을 미치는 고레버리지 지점이기 때문이다.
    * 잘못된 한 줄의 지시가 전체 코드 품질에 연쇄적 악영향을 줄 수 있다.
    * 따라서 모든 문장을 신중히 검토하고 수작업으로 작성해야 한다.

### .claude/rules

* **`rules/` 폴더 — 모듈형 규칙 관리**
    * `CLAUDE.md`가 커질 경우 `.claude/rules/` 폴더로 분리해 관리하는 것을 권장한다.
    * 각 규칙 파일은 주제별로 분리되어 유지보수가 용이하다.
        * 예: code-style.md, testing.md, api-conventions.md, security.md
    * YAML 프런트매터의 paths 필드를 사용하면 특정 경로에만 적용되는 규칙 지정이 가능하다.
        * 예: src/api/**/*.ts 경로에만 API 규칙을 적용한다.
    * 경로 지정이 없는 규칙은 모든 세션에 항상 로드된다.

### Auto Memory

* 세션 간 학습 내용을 유지하는 지속 메모리 기능이 새로 추가되었다.
* 프로젝트 컨텍스트, 디버깅 경험, 선호하는 접근 방식 등을 자동으로 기억하고, 이후 세션에서 별도 입력 없이 해당 정보를 재활용한다.
* 사용자가 별도로 기록하지 않아도 Claude가 학습 내용을 자동 저장 및 재호출한다.
* `CLAUDE.md`와 `MEMORY.md` 역할 분리가 되었다.
  * `CLAUDE.md`는 사용자가 작성하는 지침 파일로 Claude가 따라야 할 규칙과 선호 설정을 포함한다.
  * `MEMORY.md`는 Claude가 스스로 업데이트하는 메모 공간으로 세션 중 학습한 내용을 기록한다.
